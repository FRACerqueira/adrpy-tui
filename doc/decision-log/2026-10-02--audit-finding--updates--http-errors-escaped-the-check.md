# An HTTP answer broken off or not HTTP escaped the update check

**Front:** Resilience and untrusted input (Sonnet); also reached independently by Stability and concurrency (Opus) and Usability and docs against code (Fable) | **Severity:** Low | **Resolution:** Direct | **Round:** 10

CHECK_ERRORS held OSError and ValueError but not http.client.HTTPException: IncompleteRead (a connection reset mid-answer), BadStatusLine (a captive portal or proxy answering in something other than HTTP) and LineTooLong ended the update-check thread with a traceback instead of the silent failure ADR0008V01 promises. Textual captures stderr while it runs, so the traceback could only reach the person's terminal when the failure came after quitting. The passes disagreed on severity (Low-Medium, Low, Medium if corroborated); Low, the owner's call, on the stability pass's reading of that window. HTTPException is now a check error (74102ac). Red then green: tests/test_updates.py::test_an_http_answer_broken_off_or_not_http_is_an_error_the_check_can_catch, and the not-http case of tests/test_update_notice.py::test_no_newer_version_or_a_failed_check_says_nothing with thread exceptions captured.
