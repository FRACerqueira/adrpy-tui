# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project intends to follow [Semantic Versioning](https://semver.org/) once it reaches `1.0.0`.

## [Unreleased]

### Added

- **The first screens.** The header, the language choice on first run, the main menu with every adrpy and adrpy-skills command grouped by use, the `new`, `approve`, `reject`, `undo`, `version`, `revise`, `supersede` and `init` forms, the config and install-level config editors, the guided migrate builder, the `log` form, the AI skills screens (list, install, remove), change repository, the explore screen (every decision, then one decision's detail with the commands its state allows) and the check screen (a decision picker lists every decision with its label, the ones the command cannot take disabled), the confirmation screen showing the exact command line about to run, the result screen and the help of every command. Every command of adrpy and adrpy-skills has its screen.
- **Keys that can be changed** (run, preview, show all), kept per user; the key line always names the key that works.
- **Previews** (F3) of any decision or log entry from every list of them, with links between `.md` files followed; explore shows each decision's folder and filters by it; a decision-log browser.
- **Appearance presets**: Default (dark), Light and High contrast, previewed live and kept per user, with any color customizable on top of them.
- **The highlighted item stands out**: in menus and tables its whole row takes the highlight color, with its text in the cursor color (3:1 or more apart from the other rows in every preset); out of focus it keeps the cursor color; the row under the mouse is underlined.
- **Headings and table headers in help and previews** are the theme's text in bold: in Default and High contrast they were the buttons' blue, 2.36:1 on the dark screen.
- **Every screen meets WCAG contrast in every preset**, measured on everything drawn: placeholders, disabled options (a configuration group's title, a decision shown with F2), a select's arrow, unchecked radio buttons and checkboxes, and the focus border (now the highlight color) were below it.
- **Every screen opens with the focus where the keys act** -- the list, its filter or the first field; only help and previews scroll.
- **Hardening from the first pre-release audit round.** A repository's `adrpy/` folder can no longer run instead of adrpy (`python -P`). Text from files and adrpy is never read as markup, and names show bidirectional and invisible characters as `<U+XXXX>`. A read of adrpy that hangs is stopped at 60 s; a write is never stopped, can be left, and says its result is unknown, with Check at hand ([ADR0006V01](doc/adr/ADR0006V01R01-a-read-from-adrpy-that-hangs-is-stopped,-a-write-never-is,-and-a-link-in-a-file-opens-only-a-file-inside-the-repository.md)). Links open only `.md` files inside the repository. A preview renders at most 500 lines. A failure of the TUI itself is shown on its screen, with the traceback in `error.log`, instead of ending the app. A result always replaces the screen that ran its command; the command palette is off. Screens left while their content arrived, a second restart right after the first, an old migrate preview and two reads in flight no longer crash or show stale content. A long command scrolls in the confirmation. Change repository refuses an empty path and an unknown `~user`. The version check names an unreadable version instead of refusing to start. The state file is read with a BOM and written atomically. A second decision chosen in version or supersede replaces the first one's scope and domain. The skills list's columns fit every language's labels.
- **Hardening from the pre-release audit's second round.** A name that is not valid UTF-8 no longer stops the screen drawing. The rest of what adrpy and files say is shown through the same safe path. A preview is bounded in characters too (100 000). No preview opens a file outside the repository, whoever names it, nor follows a folder link inside it, and the log browser and migrate refuse a configured folder outside it. A write waiting behind a hung read can be left before it starts. While a left write still runs, another write is refused and reads still run. Quitting stops a read in flight. An empty or relative `PYTHONPATH` entry no longer lets a repository's `adrpy/` run. Keys typed while the app was busy act only on the screen in front. Enter on a migrate preview row no longer crashes. A failure whose own text fails, damaged adrpy-ai metadata and a missing home folder are handled.
- **Hardening from the pre-release audit's third round.** Every text field -- typed, pasted or filled in -- drops control, invisible and line-separator characters (a multi-line field keeps its line breaks and tabs), and a value with a line break is quoted correctly in the confirmation on Windows. A folder that cannot be read, or a folder link (a Windows junction) inside a decision or log folder, no longer crashes or loops a listing; a decision's detail reads its file through the same checks as a preview, and only its start. A left write's output is drained on Linux and macOS, so it can end. A crash no longer waits for adrpy on the way out. A write never started, and a read stopped because the TUI quits, say so instead of "still running". A refused write offers Check, and Check says when a left write still runs ([ADR0006V02](doc/adr/ADR0006V02R02-a-read-from-adrpy-that-hangs-is-stopped,-a-write-never-is,-and-a-link-in-a-file-opens-only-a-file-inside-the-repository.md)). A decision gone since explore listed it is said so. An error, folder or label of an unexpected type in adrpy's answer, and damaged adrpy-tui metadata, no longer crash; a failure note says when its details could not be written. A decision's detail offers no action while it reads the decision again.
- **Hardening from the pre-release audit's fifth round.** A failure shows the rest of adrpy's `data`, the files a count in its detail is about; the warnings of reading the configuration show on the main menu, the configuration editor and migrate; migrate compares a decisions folder written with `.` or `..` segments as adrpy does; the log browser lists neither of the log's own pages (`INDEX.md`, `CYCLES.md`), whatever the case of their names; the install-level editor no longer calls fields guarded; a configuration that cannot be read says to repair `.adrpy.json` by hand; `version`'s switch says it starts from the default template.
- **Hardening from the pre-release audit's fourth round.** A decision of an unexpected shape in adrpy's answer -- a header that is not an object, a name that is not text -- no longer ends the app when its list is filtered, and a header value that is not text is never filled into a field (a list became `--scope ab`); a configuration that is not an object still reaches the menu. A text field keeps the invisible characters a language needs (a Persian ZWNJ, an emoji's ZWJ, a BOM) and drops only the bidirectional controls and the tag characters; a value left as it opened is no change, and Change repository keeps its own path. The confirmation says when a value keeps CRLF line endings. A file field the system refuses to look at, a OneDrive placeholder taken for a folder link, a preview of CR line ends that did not say it was cut, and package metadata reaching the terminal as it was, are fixed. Check warns when a left write ran as it began to read, even if it ended meanwhile, and a run finishing after its screen closed no longer puts its result over another screen.
- **The repository config is `.adrpy.json`**, as adrpy-ai names it: the texts that name it say so, in the eleven languages. The configuration editor lists 26 fields: the plugins group is gone, and `headertablefields` is guarded like the status labels, since adrpy recognizes a decision's header by it. Migrate never offers the decisions folder's `INDEX.md`, which adrpy generates at every write of a decision.
- **The highlighted row, uncut**: explore and the log browser show, below the list, the whole values of the row under the cursor -- a column other than the last is cut to its width.
- **The Decision log group's description** says it also browses the entries.
- **The documentation reads in order**: the README says what adrpy-tui is, how it relates to adrpy-ai, which adrpy-ai versions it takes and what happens when adrpy-ai is upgraded apart from it, then covers installation, a quick start, the menus, keys, appearance and where settings are kept; every page under `doc/` opens and ends with the same line to the others, in reading order, and the other pages link back to the README.
- **The application's icon** (`src/adrpy_tui/icon.png`, kept out of the wheel) heads the README and every page under `doc/`; each page opens with a line to the README and the other pages, and the README lists them all (`tests/test_docs.py` also checks that no relative link is broken).
- **adrpy-ai's validated range**: adrpy-tui requires `adrpy-ai>=0.1.dev0,<0.2` (the 0.1 series, development builds included) and, when an adrpy-ai outside it is installed later, says so on the main menu ([ADR0003V01](doc/adr/ADR0003V01R01-adrpy-ai-is-a-declared-dependency-run-through-the-tui%27s-own-interpreter,-and-adrpy-tui-is-not-published-until-adrpy-ai-is-on-py-pi.md)).
- **Every change goes through adrpy** ([ADR0001V01](doc/adr/ADR0001V01R01-every-read-and-change-goes-through-the-adrpy-cli-as-a-subprocess,-and-the-tui-decides-on-the-json-code-and-data-only.md)), run from the TUI's own interpreter ([ADR0003V01](doc/adr/ADR0003V01R01-adrpy-ai-is-a-declared-dependency-run-through-the-tui%27s-own-interpreter,-and-adrpy-tui-is-not-published-until-adrpy-ai-is-on-py-pi.md)).
- **The UI speaks the eleven languages adrpy supports** ([ADR0005V01](doc/adr/ADR0005V01R01-the-ui-is-localized-in-adrpy%27s-languages-through-json-language-packs,-chosen-on-first-run,-while-adrpy%27s-own-responses-stay-in-english.md)). adrpy's own messages stay in English. The ten non-English packs have not been reviewed by native speakers yet.
